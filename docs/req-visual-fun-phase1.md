# 开发需求：视觉趣味化一期 —— Q 弹身体 + 情绪符号与粒子

| 项 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 日期 | 2026-09-26 |
| 模块 | `deskpaw/pet/`（主要）、`deskpaw/config/`、`tests/` |
| 运行平台 | macOS（当前开发）/ Windows（最终目标），纯本地实现，不新增任何网络依赖 |

## 1. 背景与目标

当前宠物通过"整图姿态切换 + QPainter 变换"表现动作，存在三个观感短板：

1. 跳跃、被拎起、下落时脚下没有阴影，身体呈"悬浮"状态，缺乏高度感；
2. `y_scale` 呼吸式变形存在，但落地、急停等关键瞬间没有挤压拉伸（squash & stretch）反馈，动作发软；
3. 情绪只能靠气泡文字表达，缺少漫画式符号（爱心、怒气、星星等），动作的"情绪读数"不直观。

本期目标：在不替换动画技术、不引入新第三方库的前提下，仅用 QPainter 让宠物**落地有重量、动作有弹性、情绪看得见**。

## 2. 范围

### 本期包含

- 地面接触阴影（随高度缩放、变淡）；
- 关键动作的挤压拉伸：落地、起跳/小跳、急停；
- 情绪符号系统（头顶标记，QPainter 矢量绘制）；
- 粒子系统（爱心、星星、扬尘、碎屑等，统一引擎驱动）；
- 与现有全部状态的联动配置（数据驱动，见 3.5）；
- 设置中一个"动效"开关（默认开启，关闭后只保留静态身体和气泡）。

### 本期不包含

- 全屏透明画布 / 窗口外粒子（二期）；
- 扔宠物物理、弹弓、追逐光标等新交互（二期及以后）；
- 分层骨骼动画、装扮系统、新迷你游戏；
- 音效。

约束：所有符号与粒子均在宠物自己的窗口区域内绘制，不新建窗口。

## 3. 功能需求

### 3.1 地面接触阴影

- 在宠物身体下方、窗口底边处绘制椭圆（径向渐变，中心深、边缘透明）。
- 宠物处于地面（窗口底边贴近屏幕可用区域底边）时：阴影最大、最不透明。
- 宠物离地时（被拖拽、下落过程、小跳）：阴影**留在地面位置不动**，并按离地高度等比缩小、降低不透明度。
  - 高度 0：缩放 1.0、不透明度基准值；
  - 高度 ≥ 宠物自身高度：缩放收敛到约 0.45、不透明度收敛到约 25%；
  - 中间值线性插值，曲线连续不跳变。
- 宠物睡眠/趴卧姿势因高度更低，阴影自动略扁宽。

### 3.2 挤压拉伸（squash & stretch）

在现有 `x_scale / y_scale` 基础上增加瞬时形变叠加层，形变保持"面积感"：纵向压扁时横向略微增宽（y 缩 0.88 时 x 约 1.06），反之亦然。

| 触发时机 | 形变要求 |
| --- | --- |
| 拖拽松手后落地（`drop` 结束进入 idle 的瞬间） | 触地一帧压扁（y≈0.86），约 0.25s 内回弹至 1，带回弹过冲（overshoot 约 4%） |
| 翻跟头落地（`tumble`→`dizzy`） | 更强压扁（y≈0.78），回弹约 0.4s |
| 小跳（`bounce`） | 起跳前轻微蓄力压扁，腾空时纵向拉长（y≈1.08），落地压扁后回弹 |
| 玩球急停（`chasing`→`returning` 切换瞬间） | 横向拉伸后回正 |
| 喂食（`eat`） | 每次"啃"的节拍轻微前后压缩，沿用现有正弦，不新增逻辑 |

要求：形变参数与现有呼吸形变相乘叠加，不互相覆盖；任何形变在 0.5s 内必须收敛回中性值，不得残留。

### 3.3 情绪符号

- 在宠物头顶区域绘制漫画式标记，带进场动画（弹缩：从 0.6 弹到 1.08 再回到 1.0，约 0.3s）和退场动画（0.2s 淡出上移）。
- 符号必须使用 **QPainterPath 矢量绘制**（爱心、五角星、怒气纹、感叹号、问号、音符、鼻涕泡等），不得直接使用 emoji 字符，避免 Windows/macOS 字体字形差异。
- 矢量符号首次绘制后缓存为 `QPixmap`（按当前缩放比），后续直接贴图。
- 符号与气泡同时出现时：气泡在窗口最上方，符号绘制在气泡下方、头顶上方，二者不重叠；空间不足时优先保留气泡。
- 同屏最多 1 个情绪符号，新符号触发时旧符号立即退场。

符号定义（名称 → 图形 → 默认寿命）：

| 符号 | 图形描述 | 默认寿命 |
| --- | --- | --- |
| `heart` | 心形，暖红色 | 1.4s |
| `note` | 八分音符两个 | 1.6s |
| `anger` | 怒气十字纹（💢 形） | 1.6s |
| `star` | 五角星，绕头顶旋转（眩晕时用） | 1.5s |
| `exclaim` | 感叹号 | 0.8s |
| `question` | 问号 | 1.2s |
| `snot` | 鼻涕泡，随呼吸胀缩 | 随睡眠状态 |

### 3.4 粒子系统

实现一个统一的轻量粒子引擎，在 `_tick`（40ms）中推进，`paintEvent` 末尾绘制。

- 粒子数据字段：位置（窗口坐标）、速度、角位移与角速度、寿命与已存活时间、重力系数、阻尼、图形类型、初始尺寸、淡出方式。
- 图形类型：心形、四角闪光、星点、扬尘（半透明灰圆）、碎屑（小多边形）、冲击环（描边圆环，只放大不位移）。全部矢量/简单图元，无图片资源。
- 更新规则：`v *= (1 - damp*dt)`；`vy += gravity*dt`；寿命结束按线性或渐弱曲线淡出。
- 数量上限：同时存活粒子硬上限 **80 个**，超限时丢弃最老粒子，任何情况下不得无限增长。
- 粒子生成器（emitter）按事件触发，不按帧轮询：

| 事件 | 粒子 |
| --- | --- |
| 普通落地 | 4–6 颗扬尘，向两侧低速散开 |
| 翻跟头落地 | 8–10 颗扬尘 + 3 颗星点 |
| `happy` / 握手成功 | 3–5 颗爱心向上飘 |
| `eat` | 每秒若干碎屑向嘴边散落（状态期间最多生成 2 批） |
| `bounce` 起跳 | 脚下 2–3 颗扬尘 |
| `play` | 2 颗音符 ♪ 上飘 |

### 3.5 状态联动表（数据驱动）

在 `pet.py` 中以一张配置表声明"状态 → 符号 / 循环粒子 / 形变参数"，替代在绘制代码中逐个状态写 if-else。后续模型返回 action 名时直接查此表。

| 状态 | 进入时符号 | 进入时粒子 |
| --- | --- | --- |
| `happy` | `heart` | 爱心 ×3 |
| `handshake` | `heart` | — |
| `play` | `note` | 音符 ×2 |
| `annoyed` | `anger` | — |
| `dizzy` | `star`（绕圈，持续到状态结束） | 星点 ×3 |
| `sleep` | `snot`（持续） | — |
| `drag` | `exclaim`（仅首次拎起） | — |
| `bounce` | — | 起跳扬尘 + 落地扬尘 |
| `drop` 落地 | — | 扬尘 ×4 |
| `tumble` 落地 | — | 扬尘 ×8 + 星点 |
| `eat` | — | 碎屑 2 批 |
| 其他状态 | 无 | 无 |

### 3.6 动效开关

- `Settings` 新增字段 `effects: bool = True`；设置窗口"桌面活动"分组下增加复选框"显示表情符号和粒子特效"。
- 关闭后：不生成粒子、不绘制符号；阴影和挤压拉伸保留（它们属于基础空间感，非装饰性动效）。
- 运行中切换立即生效，已存在的粒子立即清空。

## 4. 技术方案要点

1. 新增 `deskpaw/effects.py`：
   - `Particle` 数据类；
   - `ParticleSystem`：`spawn(kind, x, y, **params)`、`update(dt)`、`paint(painter)`、`clear()`；
   - `EmotionMark`：类型、起止时间，负责进场/退场插值；
   - 符号路径构造函数与按缩放比缓存的 `QPixmap` 表。
   - 该模块不依赖 `PetWindow`，更新与绘制逻辑可在 offscreen Qt 环境下单测。
2. `PetWindow` 改动：
   - 持有 `ParticleSystem` 与 `EmotionMark?`；
   - `_tick` 中推进粒子；在状态切换、落地判定等既有事件点调用 `spawn` / 显示符号（按 3.5 配置表）；
   - `paintEvent` 中按"阴影 → 身体（含形变）→ 粒子 → 情绪符号 → 气泡"顺序绘制；
   - 新增 `_landing_impact(strength)` 收口落地形变与扬尘触发，`drop` 与 `tumble` 两条落地路径统一调用；
   - 为容纳头顶符号，窗口顶部留白增加（约 `48 * ratio` 逻辑像素），身体与气泡坐标随之调整；身体底边位置保持不变。
3. 形变实现：新增 `_squash` 字段（起始时间、强度、时长、方向），每帧计算衰减系数并与现有 `x_scale/y_scale` 相乘，避免改动现有各状态的变换代码。
4. 缩放适配：所有尺寸乘以 `settings.scale/100`，与现有 `ratio` 用法一致；粒子寿命不随缩放变化。

## 5. 验收标准

功能：

1. 宠物在地面时阴影清晰；拎起到窗口顶部高度，阴影缩小到约一半并明显变淡，松手落下过程阴影随高度连续变化，落地恢复，全程无跳变。
2. 普通落地能看到"压扁—回弹—过冲—回正"；翻跟头落地形变更强且伴随星星粒子；小跳包含蓄力、拉长、压扁三个阶段。
3. 对宠物操作可依次观察到：握手成功冒爱心、连点三次冒怒气纹、翻跟头后星星绕头、睡着有鼻涕泡、被拎起瞬间感叹号、喂食有碎屑。
4. 气泡与符号同时存在时不重叠；关闭动效开关后所有符号粒子消失且不再生成，宠物其余行为（散步、玩球、聊天）不受影响。

质量：

5. 粒子同屏不超过 80 个；快速连续触发（1 秒内点击 20 次）后粒子数收敛、内存不持续增长。
6. 在 1080p、特效满载（80 粒子 + 符号）时，单帧特效部分绘制耗时 ≤ 5ms（macOS 开发机粗测，Windows 中端机 ≤ 8ms），整体保持 ≥ 30fps，目标 60fps。
7. 窗口缩放比滑块从 30% 调到 120%，符号、粒子、阴影比例正确，无错位。
8. macOS 与 Windows 11（含 125%/150% 显示缩放）下矢量符号外观一致。

测试：

9. `tests/` 新增粒子引擎单测（offscreen Qt）：位置/速度积分、寿命到期移除、数量上限淘汰、阻尼与重力；现有全部测试继续通过。

## 7. 非目标与后续衔接

- 本期不做窗口范围外的特效；二期引入"全屏透明画布（鼠标穿透）"后，粒子引擎整体迁移到该画布，即可支持扔宠物飞出、爪印轨迹、季节氛围等。
- 扔宠物物理（复用 `ball.py` 的重力/反弹参数）依赖全屏画布，列为二期首个交互。
- AI 模型侧无需改动；待模型支持返回 action JSON 后，action 名直接查询本期的状态联动表即可触发对应特效。
